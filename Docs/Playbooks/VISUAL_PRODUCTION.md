# Visual Production Playbook

> **Status:** Adopted through LAIA-2026-07-22 on 2026-07-22. This playbook does not itself grant execution permission.

## Use

Load this playbook for bounded visible production on an accepted baseline or a separately Human-authorised correction of one preserved failed-stage candidate. New or structurally material level work uses the [Level Development Lifecycle](../Level/LEVEL_DEVELOPMENT_LIFECYCLE.md) instead of treating this playbook as a shortcut around structural gates.

## Required Inputs

- exact accepted baseline or preserved Human-authorised failed-stage candidate, plus the project Production Profile;
- assignment-specific visual objective and frozen systems;
- approved art direction and representative gameplay camera;
- relevant contextual lesson IDs;
- named stage-exit review and correction allowance; and
- applicable Visual QA claims, hard fails, and evidence locations.

## Workflow

1. Verify the baseline, protected sources, and allowed visible delta.
2. Define the primary player-facing claim before editing. Supporting beauty or detail views cannot replace it.
3. Work formatively without freezing a final evidence package after each small edit.
4. Use representative materials, lighting conditions, distance, and camera before rejecting visible content or an asset family.
5. Preflight the evidence path non-mutatively when a prior capture, renderer, shader, or pipeline failure is relevant.
6. Prepare one exact candidate that satisfies the [Definition of Ready](../Production/EXECUTION_MODES_AND_STAGE_REVIEW_STANDARD.md#definition-of-ready-for-formal-review).
7. Freeze current evidence and run one meaningful stage-exit review under the [Visual Quality Assurance Workflow](../Visual/Visual_Quality_Assurance_Workflow.md).
8. Apply only the declared stage-local formal corrections, regenerate affected evidence, and rerun affected reviewers.

## Review Selection

Activate only roles whose distinct visual, spatial, technical-art, provenance, camera, gameplay-readability, evidence, or scope finding can change the stage decision. Use the full Visual Level Review Board only when the work is genuinely cross-domain, structurally material, or its risk makes every board domain decision-relevant.

## Stop

Stop before further mutation for invalid candidate identity, nonrepresentative evidence that cannot be repaired within the diagnostic allowance, an earlier structural defect, exhausted stage-local corrections, a visible hard fail outside scope, or any need for new art direction, scope, architecture, asset, licence, purchase, download, protected-source, or Git authority. Complete the factual record even when mutation stops.
